# Ключи, PSK и частные бэкапы

В A server/client keys AWG0 не меняются; ENTRY AWG1 private key также сохраняется. Оператор получает его **публичный** ключ командой `awg show awg1 public-key`. Новый EXIT создаёт свой transit key через `generate-transit-identity.sh --apply --confirm 'APPLY keys'` после inventory/preflight/согласия. В B этот шаг выполняется локально на каждом новом VPS.

После генерации каталог `/var/lib/paco-deploy/keys` — root0700, private `.key` — 0600. Скрипт выводит только `.pub`. При повторном запуске существующий private key не перевыпускается. Сверить public keys по независимому операторскому каналу; задать ENTRY_TRANSIT_PUBLIC_KEY/EXIT_TRANSIT_PUBLIC_KEY на обоих узлах. Public key не является секретом, но его подмена нарушает доверие.

PSK не передаётся здесь. Если исходный A AWG1 использует PSK, NONE блокируется; оператор локально размещает одинаковый PSK файл на обоих узлах 0600 и указывает только путь TRANSIT_PSK_FILE. Копирование PSK в env/argv/чат/лог запрещено. Без исходного PSK нужен отдельный согласованный перевод обоих peer, а не молчаливое удаление из одного конфига.

Новые private profiles B создаются после подтверждённого apply только на ENTRY, путь `/var/lib/paco-deploy/clients/<name>.conf`. Передача на устройство — вручную защищённым способом, без общего чата/публичных ссылок/терминальных QR-логов. Пока профиль хранится на ENTRY, его необходимо учитывать как секрет и включить в внешний защищённый backup. Для сценария «private key генерируется на самом клиенте» требуется отдельный рассмотренный public-only enrollment; в этом комплекте он явно отклоняется.

RESTORE использует локальный `/root/paco-private/awg0.conf`, исходный server private key, peer public keys/PSK/AllowedIPs. Без исходного server key/peer нельзя обещать перенос клиентских идентичностей. Из peer public key нельзя восстановить private profile потерянного client01. Доступные владельцу профили обновить только по Endpoint при смене IP ENTRY; проверить DNS/имя, если выбирается другая адресная схема.

SQLite/manager source/SSH keys/private client archives не загружать в чат. Для БД использовать backup API с integrity_check, не только tar работающего файла. Секретные архивы копируются оператором вне VPS; относиться к ним как к ключам всей сети. Не удалять старые profiles автоматически по отсутствию peer: исторический pacocheck мог оставить файлы для аудита, это не разрешение на чистку.
