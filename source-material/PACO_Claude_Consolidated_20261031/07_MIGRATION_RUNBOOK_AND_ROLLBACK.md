# PACO — операторский порядок действий

Это **чек-лист**, не команда на изменение инфраструктуры. Работать по одному этапу, фиксировать исходное состояние и результаты. На каждой потенциально опасной операции требуются резервная копия, страхующий rollback и подтверждение оператора.

## Сценарий A: Москва не меняется, EXIT новый
1. **Снять факты:** проверить IP/интерфейсы/версии AWG, консоли обоих VPS, нынешние правила входного UDP/60334, данные резервных копий; уточнить новый публичный IP EXIT.
2. **Backup перед изменениями:** защищённая копия AWG1 ENTRY, iptables/netfilter-persistent, rule/table 100, systemd и AWG-клиентов/менеджера; на EXIT — UFW/awg1, routes/NAT. Проверить архивацию и сохранение вне VPS. Отдельно согласованный SQLite backup.
3. **Новый EXIT:** установка на чистый VPS; ключи генерируются локально, обмен только публичными; UFW не закрывает SSH; allow UDP60334 только с ENTRY; ip_forward=1, awg1 transit, обратный маршрут client network, MASQUERADE to new WAN. Проверить синтаксис и persistence.
4. **Pre-cutover:** физический путь UDP 60334, публичные ключи/адреса/allowed IP, обратные правила, совместимость AWG; спланировать контролируемый переключатель и rollback. Проверку handshake с ENTRY без вмешательства в активный peer нельзя обещать, если нет временного тестового туннеля.
5. **Cutover / отдельно разрешено:** застраховать SSH/маршруты systemd timer; на ENTRY изменить только соединение awg1 (peer/endpoint и firewall whitelist), не трогать awg0 и Manager. При неблагоприятном результате быстро вернуться к прежнему EXIT.
6. **Проверить:** handshake, ping awg1, route get from awg0 client через awg1, UFW forward/conntrack, NAT, внешний IP тестового клиента = NEW EXIT, DNS; 53 peer и имеющиеся файлы/статистика без потерь.
7. **Commit:** подтвердить стабильность/автозагрузку, снять временную страховку только при восстановленном доступе, архивировать новое состояние на Windows, провести согласованный reboot каждого VPS отдельно; лишь затем демонтировать старый EXIT.

## Сценарий B: два новых VPS
1. Проверить одинаковую реальную ОС/совместимые AWG и доступ provider console; IP/порты/сети/конфликты/бэкапы. Определить стратегию identity: перенос старых ключей или новые.
2. Настроить новый EXIT: AWG1, forwarding, обратная route, firewall, NAT, persistence. Не разрешать исходящие клиенты до готовности.
3. Настроить ENTRY: firewall, fail-closed и independent policy rule/unreachable fallback с автозагрузкой **до AWG0**; настроить AWG1 и проверить transit.
4. Перенести из защищённых offline-копий старый AWG0 или локально создать новые ключи/peer; полный профиль Jc/Jmin/Jmax/S1-S4/H1-H4, MTU, DNS, UDP/60333. Проверить правомочность каждого файла, mode 0600.
5. Смена IP ENTRY требует обновить Endpoint клиентам; если ключей нет — выдача новых конфигов. Вначале тестовый клиент, затем миграция остальных.
6. Менеджер и history SQLite переносить отдельно; скрипт текущей версии содержит hardcoded ENTRY endpoint и сеть — проверить и согласованно изменить под новый ENTRY, без автоматической подмены списка клиентов.
7. Acceptance tests, продуманное переключение пользователей/доменов, go/no-go, reboot EXIT → ENTRY по одному узлу и новые защищённые резервные копии вне VPS.

## Минимальный план отката
- Сохранять старый EXIT в рабочем состоянии при сценарии A до commit.
- Для каждой операции: файл backup, снимок runtime interfaces/rules/routes/iptables/UFW/systemd, точная обратная команда и таймер автоматического возврата для опасного cutover.
- Откат не должен удалять AWG0 клиентские ключи/peer.
- Для rollback маршрутной таблицы 100 нельзя бездумно `flush table 100`: он удаляет защитный unreachable fallback. Восстанавливать policy rule/failclosed до возврата клиентского VPN.
- Проверить после rollback: SSH с разрешённого адреса, old AWG1 handshake, old EXIT IP у клиента, fail-closed в норме, прежнее число peers, timer SQLite активен.

## Стоп-сигналы
Нет консоли/второго SSH; новый EXIT IP/WAN IF неизвестны; несовместимый AWG; конфликт внутренних сетей; firewall не пропускает вернувшийся трафик; missing return route; NAT нет; нет тестового выхода через EXIT; `ip route get ...` возвращает WAN ENTRY; SSH whitelist непроверен; не восстановлен unreachable/failclosed; rollback не гарантирован.
