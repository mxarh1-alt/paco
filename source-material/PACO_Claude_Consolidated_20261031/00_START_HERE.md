# PACO — консолидированный комплект для Клары
**Срез фактов: 31 октября 2026. Назначение: подготовка воспроизводимых Bash-скриптов развёртывания каскадного VPN.**

Этот комплект **не выполняет изменений** и **не содержит секретов**. Включённый Bash-файл — только read-only аудит. Он не заменяет резервные копии ключей и конфигураций, которые остаются у оператора.

## Как передать Кларе
1. Передайте **весь ZIP-архив**, а не отдельный промпт. Начальный документ для неё — `01_CLAUDE_MASTER_TASK.md`.
2. Скажите: «Используй только приложенные подтверждённые данные, подготовь готовые Bash-скрипты для сценариев A и B, но не запускай их».
3. Сценарий **A**: прежняя Москва ENTRY остаётся, полностью новый EXIT. Сценарий **B**: два новых VPS с одинаковой версией ОС.
4. `03A...` уже содержит известные сведения по нынешней Москве и незаполненные поля нового EXIT. `03B...` — заготовка для двух новых VPS. Неизвестные значения помечены `TO_CONFIRM` / `TO_FILL`; **их не следует угадывать**.
5. `04_paco_readonly_audit.sh` можно запускать только вручную под root: `bash 04_paco_readonly_audit.sh entry|exit`; отчёт просмотреть перед передачей (там IP/имена хостов, но нет приватных ключей).
6. Полученный от Клары **код проверяем до использования**: аудит → экспертиза → тестовый VPS → согласие оператора → изменение рабочей сети в согласованное окно.

## Что внутри
- `01_CLAUDE_MASTER_TASK.md` — точное задание Кларе на **готовые скрипты**, а не только аудит.
- `02_PACO_AS_BUILT_CONFIRMED.md` — проверенная конфигурация и оговорённые границы знаний.
- `03A_NEW_SERVER_INVENTORY_EXIT_REPLACEMENT.txt` — сценарий A, уже заполненная часть.
- `03B_NEW_SERVER_INVENTORY_TWO_NEW_VPS.txt` — сценарий B, шаблон новых VPS.
- `03_NEW_SERVER_INVENTORY_TEMPLATE.txt` — универсальный шаблон для последующих замен.
- `04_paco_readonly_audit.sh` — только чтение, исходный проверенный скрипт PACO.
- `05_MOSCOW_AUDIT_ACTUAL_20261031.txt` — фактический предоставленный вывод московского аудита.
- `06_EXIT_KNOWN_STATE_AND_GAPS.md` — подтверждённое состояние Алматы, отсутствие свежего полного аудита.
- `07_MIGRATION_RUNBOOK_AND_ROLLBACK.md` — пошаговый план и точки остановки для оператора.
- `08_TEST_PLAN_AND_FAILURE_MODES.md` — обязательные проверки, включая fail-closed и reboot.
- `09_MANAGER_AND_BACKUPS.md` — что переносить с менеджером клиентов; сохранность SQLite.
- `10_CLAUDE_DELIVERABLES_AND_REVIEW.md` — перечень файлов, которые должна вернуть Клара, критерии приёмки.
- `SHA256SUMS.txt` — хеши файлов комплекта.

## Важное
- Фактические публичные адреса действующих VPS приведены **только как история/для сценария A**. Сценарий B не должен их копировать.
- Подмена только EXIT **не должна затрагивать AWG0 клиентов**. Замена ENTRY с новым IP потребует обновления клиентских Endpoint либо сохранения прежнего адреса/имени и достижимости.
- Dante/SOCKS5 вне проекта восстановления каскада. Его диагностику не включать в установочные сценарии.
- В текущем PACO был проверен отказ **основного маршрута**: отказ полного AWG1/отсутствие IPv6-утечек ещё требует самостоятельной валидации на новой площадке.
