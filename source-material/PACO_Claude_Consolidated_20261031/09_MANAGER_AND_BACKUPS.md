# PACO: управление клиентами, статистика и резервные копии

## Рабочая подсистема клиента на текущем ENTRY
- Менеджер: `/usr/local/sbin/paco-awg.py`, короткая команда `paco-awg` (симлинк), проверенная версия **v0.2.4**.
- Серверный AWG0: `/etc/amnezia/awg0.conf`, клиентские `.conf` и `.png` в `/root/awg-client/`, права 0600; при фиксации 53 peer, 52 `.conf`, отсутствует конфигурация `client01` (10.77.77.2) — peer сохранять.
- Импорт/создание, QR, статистика и удаление проверены на тестовых `testpaco`/`pacocheck`; последнего удалили, его клиентские файлы могли остаться для аудита. Удаление требует ввести **полную строку** `REMOVE имя`.
- `paco-awg-traffic.service` (oneshot) и `paco-awg-traffic.timer`, цикл 60 секунд; SQLite `/var/lib/paco-awg/traffic.sqlite3`. Таблицы `peers(pub,name,client_ip,added_at)`, `counters(pub,rx,tx,last_seen,handshake)`, `daily(pub,day,rx,tx)`.
- `paco-awg list`: имя, IP, давность handshake в минутах, RX/TX месячные и с начала учёта. `never` не значит «никогда в жизни», а текущую отсутствующую запись о handshake. RX/TX значения — перспектива счётчиков AWG сервера.
- Генератор v0.2.4 включает параметры AWG `Jc/Jmin/Jmax,S1-S4,H1-H4`, `MTU=1380`. Серверный процесс AWG0 при штатных добавлениях не перезапускался; использовался `awg syncconf`.

## Где настоящий риск при переносе
- Скрипт v0.2.4 содержит жёстко заданные `ENDPOINT='217.199.252.90:60333'`, `INTERFACE='awg0'`, `NET='10.77.77.0/24'`. **В B** изменить/проверить всё под новую ENTRY и сохранить пользовательские ключи, если миграция именно старых клиентов. Не распространять исходник v0.2.4 как универсальный для других проектов без явной адаптации.
- Для A менеджер и клиентские конфиги остаются без изменений: EDGE/ENTRY IP прежний.
- Для B перенос приватных ключей допускается только локально из защищённой копии владельца. Нельзя спрашивать эти файлы в чате или в отчётах.
- SQLite: `PRAGMA quick_check` работающей базы вернул `ok`; tar в момент записи **не гарантирует консистентность** SQLite. Делать API `sqlite3.Connection.backup()` в отдельный файл, затем `PRAGMA integrity_check`, хранить защищённо вместе с остальным бэкапом. Не сбрасывать исторические данные.
