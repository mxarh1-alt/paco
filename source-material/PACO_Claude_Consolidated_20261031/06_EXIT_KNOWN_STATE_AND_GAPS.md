# EXIT (Алматы) — исторические проверенные данные и пробелы

**Важное ограничение:** полноценный новый вывод `04_paco_readonly_audit.sh exit` от оператора в переписке ещё не получен. Данные ниже — результаты ранее выполненных вручную проверок и контрольного reboot **30.10.2026**, а не снимок всех настроек 31.10.

```
Host: ala-1-vm-3lss
Public IPv4: 72.56.2.102
WAN: eth0
AWG1: 10.88.88.2/30; UDP 60334
Return route: 10.77.77.0/24 dev awg1
SNAT: iptables -t nat POSTROUTING -s 10.77.77.0/24 -o eth0 -j MASQUERADE
UFW: active
Ingress UDP/60334: allow from 217.199.252.90 only
UFW route allow: from 10.77.77.0/24 in on awg1 out on eth0
```

Ранее проверенные службы: `awg-quick@awg1.service` enabled + active; `ufw` active; systemd failed units: 0. После reboot 30.10.2026 с временем загрузки `13:51:54 UTC` маршрут и NAT присутствовали; Москва успешно пинговала `10.88.88.2`, 3/3 пакета, ~49 мс. Внешний IP клиента подтверждён как `72.56.2.102`.

Техническая история: бывший EXIT awg0 со старой сетью 10.77.77.0/24 отключён из-за конфликта маршрутов; UFW `/etc/ufw/before.rules` ранее содержал ошибочную строку, её исправили и проверили файлы с `iptables-restore --test`. Подгрузка правил требовала `ufw reload`, простой `systemctl restart ufw` не всегда применял изменения. Не применять эти старые костыли без проверки конкретного нового EXIT.

**Пробелы:** фактический `/etc/os-release`, версия/пакеты AWG, новая inventory exit, current SSH whitelist, client IPv6 policy, статус полного исходящего firewall и содержимое ключей (сознательно не собираются). Перед развёртыванием нового EXIT выполнить read-only audit и проверить WAN/доступ провайдера.

**Вне задачи:** на историческом EXIT были открытые SSH TCP/22, TCP/8080, TCP/8888, UDP/60333 (некоторые также для IPv6); требуют отдельного аудита безопасности при миграции, но массово закрывать их без знания назначения нельзя.
